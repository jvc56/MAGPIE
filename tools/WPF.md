# WordPlusFloater tables

WPF adds an optional positional filter to WIT move generation. A cell fixes a
contiguous base word, one other board letter at a signed offset, and the final
word length. Its mask contains letters occurring outside those fixed tile
occurrences in any matching dictionary word. Intersecting these masks with the
ordinary WIT mask can rule out racks and subracks before wordmap lookup.

First rebuild the ordinary WIT with this engine's residual-letter masks. The
release build preserves an existing WIT, so regenerate it explicitly:

```sh
make magpie BUILD=no_pgo_release
printf 'convert kwg2wit CSW24\n' | \
  bin/magpie 'set -lex CSW24 -wmp true -rit false -wit false'
```

Then generate a WPF table with Python 3.8 or newer (no third-party packages):

```sh
python3 tools/generate_wpf.py \
  --wit data/lexica/CSW24.wit \
  --dictionary data/lexica/CSW24.txt \
  --bases tools/wpf/CSW24-top2560.txt \
  --output data/lexica/CSW24.wpf
```

Use a WIT generated by the current engine and the matching complete uppercase
A-Z text lexicon. The generator checks every playable word against the WIT,
including lengths outside the selected bases, before publishing output. Words
longer than the WIT board dimension are ignored. Incomplete or mismatched
lexica are rejected; an existing output remains intact on failure. A successful
run prints the output hash and size. Put `NAME.wpf` beside the lexicon data under
the configured data paths; the engine loads it when that lexicon's WIT is used.
Missing WPF files retain ordinary WIT behavior. Build/train PGO with the same
optional table that will be used for production work.

`--bases` selects which length-2 through length-4 words receive complete rows.
Omit it to cover every base of those lengths. A custom file contains one
uppercase word per line; every entry must be a WIT key. Input ordering and
duplicates do not affect output. Selecting fewer bases changes filter coverage,
not the dictionary: every retained row still includes **all** matching words.
An omitted row supplies no positional constraint. A covered zero cell supplies
an empty addable set. These cases must remain distinct.

The supplied CSW24 list fixes 2,560 bases: 127 length-2, 1,295 length-3 and 1,138
length-4 words. It was selected by candidate-base opportunity frequency in one
million static autoplay games. Selection does not need to be repeated to regenerate
the table. Its SHA-256 is
`8a231bcd10fe81d0b39e7301f50ee44877f2b6a5ae48a36c1194114daa1900d4`.
With the matching 15-square CSW24 WIT layout, output is 39,065,048 bytes with
SHA-256 `6eada4c41fd8ab6e78fab50ef06e087625cbf42e073da1fcd494be6a45447855`.
That layout has KWG fingerprint `9283346135631466225` and WIT key-layout
fingerprint `12770297558071208977`. A different valid trie layout can produce
different bytes; always regenerate WPF when regenerating its WIT.

Run the generator's small independent-oracle tests with:

```sh
python3 -m unittest discover -s test -p wpf_generator_test.py
```

## Compact file format

All integers are little-endian. The generator writes M2 format:

| Field | Type |
| --- | --- |
| Magic `WPFM2LE` followed by NUL | 8 bytes |
| Board dimension, minimum base length (2), maximum base length (4), reserved (0) | 4 × uint32 |
| KWG fingerprint, WIT key-layout fingerprint | 2 × uint64 |

Each base length has a section of four uint32 values: base length, original WIT
value count, cells per stored row, and stored row count. It is followed by one
int32 per original WIT value (`-1` for omitted, otherwise a compact row index),
then the stored rows of uint32 masks. Compact rows follow original WIT value-ID
order. Bit 1 denotes A, bit 26 denotes Z, and bit 0 is unused. Covered all-zero
rows are retained.

For base length `b`, final length `n`, and extension `e = n - b`, valid floater
offsets relative to the base start are `[-e, -1]` and `[b, n - 1]`. Offsets inside
the base are excluded. Their local offset index is `delta + e` on the left or
`e + delta - b` on the right. The cell index is
`(e * (e - 1) + offset_index) * 26 + machine_letter - 1`.
A row has `26 * (dimension - b) * (dimension - b + 1)` cells.

The layout fingerprint uses the engine's FNV recurrence, initial state
`1469598103934665603`, multiplier `1099511628211`, modulo 2^64. For each complete
WIT length-2 through length-4 trie, hash its length, node count, root and value
count as four little-endian uint32 values, followed by its tile-byte array,
sibling-last-byte array, uint32 children and int32 value IDs. Ordinary WIT
addable masks are excluded. The engine verifies the board dimension, KWG and
layout fingerprints before using any row.
